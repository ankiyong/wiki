0. 수업 목표

ChatGPT의 최신 기능 흐름을 이해하고, 업무 자료를 만들 때는 GPT Work, 코드 변경과 검증이 필요할 때는 Codex를 선택하는 기준을 익힙니다.

GPT 기능 지도Work/Codex 비교요청 공식승인 기준

1. GPT 모델 선택

같은 GPT라도 작업 목적에 따라 빠른 응답, 깊은 사고, 심층 리서치 모드를 다르게 선택합니다.

Instant단순 질문, 짧은 설명, 빠른 아이디어처럼 속도가 중요한 작업에 사용합니다.
Thinking비즈니스 판단, 경제·전략 고민, 복잡한 비교처럼 논리와 정확도가 필요한 작업에 사용합니다.
Pro가장 깊은 분석, 장문의 리서치, 근거가 많은 보고서처럼 품질을 우선할 때 사용합니다.
Auto내가 고르기 어렵다면 GPT가 질문 난이도에 맞춰 응답 시간을 판단하게 둡니다.

수업 활용 포인트

빠른 답은 Instant/Auto, 중요한 판단은 Thinking/Pro로 바꿔보며 결과 차이를 비교합니다.

2. GPT 앱 연동

@ 명령어로 외부 앱을 연결하면 GPT 대화가 콘텐츠 제작·디자인·정리 작업으로 확장됩니다.

Adobe Express포스터, 카드뉴스, 간단한 홍보 이미지처럼 빠른 콘텐츠 제작에 적합합니다.
Adobe Photoshop이미지 밝기, 노출, 색감, 세부 보정처럼 정밀한 리터칭에 적합합니다.
Figma디자인 페이지, 서비스 흐름, 콘텐츠 제작 플로우를 시각적으로 정리할 때 유용합니다.

예시 요청

@Adobe Express 겨울 바다와 따뜻한 아메리카노 분위기의 카페 홍보 포스터 시안을 만들어줘. 텍스트는 적게 넣고, 따뜻한 색감과 감성적인 사진 느낌으로 만들어줘.

3. Agent Mode

Agent Mode는 GPT가 웹과 연결 도구를 오가며 여러 단계를 스스로 수행하는 자동화형 작업 방식입니다.

연결 가능한 맥락Google Drive, Notion, Slack 같은 업무 자료와 대화 기록을 탐색할 수 있습니다.
자동 탐색웹사이트, 보고서 PDF, 자료 페이지를 열어 필요한 정보를 수집합니다.
결과 생성시장 조사 보고서, 발표자료, 요약표처럼 완성된 산출물을 만들 수 있습니다.
주의메일 전송, 게시, 외부 시스템 변경은 반드시 승인 후 진행해야 합니다.

수업에서는 “AI가 자동으로 일하게 할 수 있다”보다 “승인 지점이 있는 업무 흐름”으로 설명합니다.

4. Deep Research

Deep Research는 웹과 지식 데이터를 종합해 출처가 있는 전문 보고서를 만드는 기능입니다.

역질문조사 범위, 기간, 조건을 GPT가 먼저 물어볼 수 있습니다.
출처 패널참고한 웹사이트와 자료 링크를 함께 보여줍니다.
보고서 구조목차, 요약, 근거, 결론 형태로 긴 문서를 작성합니다.
검토 필요출처가 있어도 날짜, 수치, 주장 해석은 사람이 재확인해야 합니다.

예시 요청

2026년 국내 생성형 AI 교육 트렌드를 조사해줘. 공식 발표와 신뢰도 높은 기사 중심으로 정리하고, 대상별 교육 수요, 주요 기능, 주의사항을 표로 정리해줘. 출처와 기준일을 함께 표시해줘.

5. Canvas

Canvas는 긴 글을 별도 문서 편집창에서 다듬는 기능입니다. 대화창과 문서 편집창을 나눠 작업합니다.

긴 글 작성강의 소개문, 블로그 글, 안내문처럼 긴 문서를 작성합니다.
부분 수정특정 문장이나 문단을 지정해 고칩니다.
난이도 조정중학생 수준, 전문가 수준처럼 독해 난이도를 바꿉니다.
최종 다듬기문체, 이모지, 표현, 글자 수를 조정합니다.

문서가 길어질수록 일반 채팅보다 Canvas에서 수정 지점을 보며 작업하는 편이 좋습니다.

6. GPTs / Projects

GPTs는 목적별 전용 챗봇이고, Projects는 대화와 파일을 주제별로 묶어 맥락을 재사용하는 폴더입니다.

GPTs
  • 주식 분석, 부동산, 유튜브 대본처럼 목적별 챗봇 사용
  • 사전 프롬프트와 자료가 들어간 전용 도구처럼 활용
  • 공개 GPT는 정확성·출처·개인정보를 별도 확인
Projects
  • [채널] 마케팅/SNS, [사업] 비즈니스처럼 주제별 폴더 관리
  • 관련 대화와 파일을 묶어 반복 업무 맥락 유지
  • 장기 프로젝트는 결정사항과 기준 문서를 함께 보관

반복되는 업무는 GPTs로 역할을 고정하고, Projects로 맥락을 묶어두면 재사용성이 높아집니다.

7. Chat / Work / Codex 선택법

선택 기준은 주제가 아니라 최종 결과물입니다.

Chat

답변만 빠르게 필요할 때

  • 질문
  • 개념 설명
  • 짧은 요약
  • 문장 다듬기
GPT Work

업무 산출물을 완성할 때

  • 시장조사
  • 보고서
  • 발표자료
  • 스프레드시트
  • 회의록·정기 리포트
Codex

코드를 바꾸고 검증할 때

  • 버그 수정
  • 기능 구현
  • 리팩터링
  • 테스트·빌드
  • PR 검토·배포 준비

한 문장 요약: 업무 자료는 Work, 코드 변경은 Codex, 빠른 답변은 Chat입니다.

8. GPT Work와 Codex 비교

Work는 자료와 산출물이 중심이고, Codex는 작업공간과 검증이 중심입니다.

기준GPT WorkCodex
핵심 목표검토 가능한 업무 결과 완성검증된 기술 변경 완성
주요 맥락문서, 웹, 파일, 플러그인, 연결 서비스저장소, 소스코드, 로그, 터미널
대표 결과보고서, 슬라이드, 표, PDF, 사이트 초안코드 변경, 테스트, 리뷰, 빌드 결과
검토 기준내용, 구조, 출처, 시각적 완성도diff, 테스트, 타입 검사, 실행 결과
좋은 요청대상 독자, 자료 범위, 형식, 품질 기준작업 위치, 재현 조건, 제약, 검증 명령

9. Work 실습 — 업무 산출물 요청

Work 요청은 결과물, 자료 범위, 대상 독자, 형식, 품질 기준, 승인 지점을 구체적으로 써야 합니다.

요청 공식

결과물 + 자료 범위 + 대상 독자 + 형식 + 품질 기준 + 승인 지점

실습 프롬프트

첨부한 회의록 5개를 바탕으로 결정사항, 담당자별 할 일, 마감일, 리스크를 표로 정리해줘. 대상은 팀장 보고용이고, 분량은 1페이지 이내로 해줘. 근거가 부족한 내용은 “확인 필요”라고 표시해줘. 외부로 전송하지 말고 초안만 만들어줘.

Work는 “사람이 검토하고 바로 활용할 업무 자료”를 만들 때 가장 자연스럽습니다.

10. Codex 실습 — 기술 작업 요청

Codex 요청은 작업 위치, 문제, 재현 방법, 제약, 검증 명령, 보고 형식이 중요합니다.

요청 공식

작업 위치 + 문제/목표 + 재현 방법 + 제약 + 검증 명령 + 보고 형식

실습 프롬프트

현재 저장소에서 로그인 후 세션이 만료되는 문제를 재현해줘. 원인을 찾은 뒤 최소 범위로 수정하고, 관련 회귀 테스트를 추가해줘. 데이터베이스 스키마는 바꾸지 말고, 수정 후 인증 관련 테스트를 실행해서 원인, 변경 파일, 테스트 결과, 남은 위험을 요약해줘.

Codex는 설명만 하는 것이 아니라 파일 변경과 테스트 결과로 작업을 증명해야 할 때 적합합니다.

11. 함께 쓰는 업무 흐름

복잡한 프로젝트는 Work와 Codex를 연결하면 더 안정적입니다.

1. Work조사·요구사항·기획 자료 작성
→
2. Codex저장소 분석·구현·테스트
→
3. Work릴리스 노트·고객 공지·교육자료 작성
예시 1Work로 경쟁사 분석표 작성 → Codex로 기능 구현 → Work로 발표자료 작성
예시 2Codex로 버그 수정 결과 정리 → Work로 고객 안내문과 내부 보고서 작성

중간에는 반드시 사람이 승인합니다: 조사 → 요구사항 승인 → 구현 → 테스트 확인 → 공지 작성.

12. 보안·승인·검토

도구가 강력할수록 입력 자료, 권한, 외부 동작을 더 명확히 통제해야 합니다.

Work 주의메일 전송, 게시, 캘린더 수정, 외부 시스템 변경 전에는 승인 지점을 둡니다.
Codex 주의작업 폴더, 쓰기 권한, 네트워크, 삭제·배포·푸시 권한을 제한합니다.
공통 주의개인정보, 비밀키, 내부 민감 문서, 고객 정보는 입력하지 않습니다.
최종 확인출처, 숫자, 코드 변경, 테스트 범위, 보안 위험을 사람이 검토합니다.

오늘 기억할 문장

완성된 업무 자료는 Work, 검증된 코드 변경은 Codex, 빠른 답변은 Chat입니다.
